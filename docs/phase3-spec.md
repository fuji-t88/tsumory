# フェーズ 3 詳細仕様（写真・音声）

つぶやきに写真を 1 枚まで添付できるようにし、本文を音声認識でも入力できるようにする。
フェーズ 1・2 の仕様（[phase1-spec.md](phase1-spec.md)・[phase2-spec.md](phase2-spec.md)）を土台にし、この仕様書には**追加・変更する部分だけ**を書く。食い違う場合は、この仕様書を正とする。
パッケージ構成・コーディング規約・禁止事項は [CLAUDE.md](../CLAUDE.md) に従う。仕様書の一覧は [spec.md](spec.md)。

要件・受入条件・テストケース・マイルストーンは、リポジトリ直下の WBS（`WBS_tsumory.md`。Excel は `WBS_tsumory.xlsx`）で管理する。この仕様書は、WBS の要件を実装に入れる粒度まで詳しくしたもので、要件 ID（`PH-REQ-01` など）で WBS と対応させる。WBS と食い違う場合は、この仕様書を正とし、WBS を直す。

## 2. 写真の保存先（PostgreSQL）

写真は、アプリの DB（PostgreSQL）の `post_photos` テーブルに、バイナリ（`BYTEA`）で保存する。

- WBS の D-04 では、Railway の非公開のオブジェクトストレージ（S3 互換のバケット）を第一候補にしていた。2026-11-20 に Railway の試用期間が終わり、無料のまま続けると決めたので、外部のストレージを使わない形に変えた
- DB に入れる理由
  - 追加のサービス・料金・資格情報が要らない
  - つぶやきと写真を同じトランザクションで保存・削除できる。DB とストレージの食い違い（片方だけ残る、孤立したファイル）が起きないので、WBS の D-07（補償処理と清掃）が要らなくなる
  - つぶやきを消すと、写真も外部キーの `ON DELETE CASCADE` で一緒に消える（PH-REQ-13 の「投稿の削除で画像が使えなくなる」を DB が守る）
- 引き受けること：DB が写真の分だけ大きくなる（1 枚 5MB まで × 1 日 16 件まで）。バックアップと復元に時間がかかるようになる
- 見直す条件：DB の大きさが無料の枠や性能の限界に近づいたとき、複数の写真や大きな画像を扱うことになったとき。そのときは外部のストレージに移し、D-07 の補償処理を設計する
- 写真は `posts` とは別のテーブルにする。つぶやきの一覧・検索・日記の生成で `posts` を読むときに、写真のバイナリを読まないため

## 3. データベース

### マイグレーション

`V4__create_post_photos.sql` で `post_photos` を作る。

### `post_photos`

| 列 | 型 | 制約 | 説明 |
|---|---|---|---|
| `post_id` | `BIGINT` | 主キー、`posts(id)` への外部キー（`ON DELETE CASCADE`） | 写真を添付したつぶやき。主キーなので、1 つのつぶやきに写真は 1 枚まで |
| `content_type` | `VARCHAR(100)` | `NOT NULL` | 写真の形式（`image/jpeg` など）。許す形式は PH-REQ-02 で決める |
| `size_bytes` | `INTEGER` | `NOT NULL`、`data` の長さと同じ | 写真の大きさ（バイト） |
| `data` | `BYTEA` | `NOT NULL`、空でない | 写真のバイナリ |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL` | 写真を保存した日時 |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL` | 写真を差し替えた日時（差し替えていなければ `created_at` と同じ）。`V5__add_updated_at_to_post_photos.sql` で足した |

- 「1 つのつぶやきに 1 枚まで」は、主キー（`post_id`）で DB が守る
- 検査制約で守るもの：`data` が空でない、`size_bytes` が `data` の長さと同じ（内部一貫性。CLAUDE.md の「入力の検証（多層防御）」）
- 容量の上限（5MB。PH-REQ-03）と形式（PH-REQ-02）は、仕様が変わりうる業務ルールなので、DB の検査制約には入れない
- 差し替え（PH-REQ-05）は、行を書き換える（前の写真のデータは残らない）

## 4. ドメインモデル（`domain/`）

`PostPhoto`（エンティティ。`post_photos`）を足す。

- `Post` との関係は `PostPhoto` の側だけが持つ（`@OneToOne(fetch = LAZY)` + `@MapsId`）。`Post` には写真への参照を持たせない（つぶやきを読むたびに写真を読まないため）
- コンストラクタ `PostPhoto(Post post, String contentType, byte[] data, Instant now)` で、内部一貫性を確かめる
  - 値が `null` なら `NullPointerException`
  - `contentType` が空・空白だけ・100 文字を超えるとき、`data` が空のときは `IllegalArgumentException`
- `data` は受け取るときと返すときに複製する（外から書き換えられないように）
- `replace(contentType, data, now)` で差し替える。コンストラクタと同じ決まりを、すべての値について確かめてから書き換える（途中で失敗して、一部だけ書き換わった状態にしない）。`created_at` は変えず、`updated_at` を変える

## 5. 画面

### 今日のつぶやき（変更。`templates/home.html`、`/`）

投稿フォームに、写真を選ぶ欄を足す。

```
┌ いまの気持ちをつぶやく ────────────────┐
│ ┌──────────────────────────┐ │
│ │（本文）                              │ │
│ └──────────────────────────┘ │
│ 写真（任意・1 枚まで） [ファイルを選択]    │
│                              [つぶやく] │
└──────────────────────────────┘
```

- フォームは `enctype="multipart/form-data"` で送る
- ファイルの欄（`<input type="file" name="photo">`）は 1 つだけで、`multiple` を付けない
- 写真を選ばなくても投稿できる（任意）
- 入力チェックで画面を出し直すとき、選んだ写真は残らない（ブラウザの仕様）。本文は残る
- 投稿の上限に達しているときは、本文の欄と同じく写真の欄も無効にする
- 写真の欄の下に、受け付ける形式と大きさの案内（「JPEG か PNG・5MB まで」）を出す。`accept` は `image/jpeg,image/png`
- 写真を選んだらすぐに、その写真をフォームの中にプレビューする（PH-REQ-04）。横の「写真を外す」で選択を取り消せ、外したあとは写真の欄にフォーカスを戻す。プレビューはブラウザの中だけで作り（`URL.createObjectURL`）、送る前にサーバーへは送らない。Content-Security-Policy を入れるときは、`img-src` に `blob:` を許す
- 送る前に、ブラウザでも形式と大きさを確かめる（`static/js/photo-input.js`）。受け付けないファイルを選んだら、選ばなかったことにして、サーバーと同じメッセージを出す。数字とメッセージは、サーバーが `data` 属性で渡す（JavaScript に書かない）。JavaScript が無効でも、サーバーが同じ決まりで断る
- 添付した写真を一覧に表示するのは PH-REQ-11 で作る

### 今日のつぶやき（編集モード）

編集のフォームにも写真の欄を置き、差し替え（PH-REQ-05）と外す（PH-REQ-06）をできるようにする。編集できるのは、これまでどおり今日と昨日のつぶやきだけ。

```
│ ┌──────────────────────────┐ │
│ │（本文）                              │ │
│ └──────────────────────────┘ │
│ [カテゴリ ▼]                              │
│ ┌────┐                                  │
│ │（今の写真）│ ☐ 写真を外す（本文は残ります）       │
│ └────┘                                  │
│ 写真を差し替える（任意） [ファイルを選択]       │
│                       [キャンセル] [保存]  │
```

- フォームは `enctype="multipart/form-data"` で送る
- 写真のあるつぶやき：今の写真のサムネイルと「写真を外す（本文は残ります）」のチェックを出し、ファイルの欄の見出しは「写真を差し替える（任意）」
- 写真のないつぶやき：チェックは出さず、見出しは「写真を添付する（任意）」（編集で写真を足せる）
- 新しく選んだ写真のプレビューと、選択の取り消し（「選んだ写真を取り消す」）は、投稿フォームと同じ（`photo-input.js`）。取り消しのボタンは、今の写真を外すチェックと紛らわしくならない文言にする
- 写真を選ばず、チェックも入れなければ、写真は変えない
- 入力チェック：投稿フォームと同じ（1 枚まで・形式・大きさ・中身）。加えて、「写真を外す」と差し替える写真を同時に選んだら「写真を外すか差し替えるか、どちらかにしてください」で断る
- チェックボックスはチェックしないと値が送られないので、値がなければ「外さない」とする

### 音声入力

投稿フォームの本文の欄に、音声認識で文字を入れられるようにする（VC-REQ-01〜12）。音声は入力の手段の 1 つで、認識した文字は手で入力した文字と同じく、本文の欄に入るだけ。投稿の決まり（100 文字・改行なし・見えない文字なし・1 日 16 件）は、これまでどおりサーバーが確かめる。

```
│ ┌──────────────────────────┐ │
│ │（本文）                              │ │
│ └──────────────────────────┘ │
│ [音声で入力]  音声入力を使えます               │
│   ↓ 押すと                                  │
│ [停止] [キャンセル]  聞き取っています…（途中経過） │
│ 音声はブラウザの音声認識で文字にします。…         │
```

- 仕組み：ブラウザの Web Speech API（`SpeechRecognition`。Chrome は `webkitSpeechRecognition`）。処理は `static/js/voice-input.js`。サーバーの API は足さず、音声も文字もサーバーには送らない（送るのは、ユーザーが「つぶやく」を押したときのフォームだけ）。録音もしない（VC-REQ-09）
- 対象：PC の Chrome と Edge（VC-REQ-01）。言語は日本語（`ja-JP`）
- 置き場所：投稿フォームの本文の欄の下だけ。編集フォームには置かない（WBS の対象は「つぶやき欄」）。投稿の上限に達して本文の欄が無効なときは出さない
- 対応していないブラウザ（Firefox など）：ボタンは出さず、「このブラウザでは音声入力を使えません。キーボードで入力してください。」と出す。キーボードの入力はそのまま使える（VC-REQ-07）。JavaScript が無効なら、どちらも出ない
- 案内（VC-REQ-10）：ボタンの下に、いつも次を出す。「音声はブラウザの音声認識で文字にします。ブラウザによっては、音声が外部の認識サービスに送られます。Tsumory のサーバーには音声を送らず、保存もしません。音声入力を使わずに、キーボードで入力することもできます。」
- マイク：画面を開いただけでは、マイクの許可を求めない。「音声で入力」を押したときに、ブラウザが許可を求める（VC-04）

#### 状態と操作（VC-REQ-02・05・12）

| 状態 | 出すボタン | 状態の欄 | 本文の欄 |
|---|---|---|---|
| 待機 | 音声で入力 | 「音声入力を使えます」・前回の結果・エラー | 入力できる |
| 聞き取り中 | 停止・キャンセル | 「聞き取っています…話し終えたら「停止」を押してください」と、確定前の途中経過 | 読み取り専用（手の入力と音声の結果をぶつけない） |
| 終了中 | 停止・キャンセル（押せない） | 「終了しています…」 | 読み取り専用 |

- 状態の欄は `role="status"`・`aria-live="polite"` にして、読み上げにも伝える。ボタンはどれも `<button type="button">` で、キーボードで操作できる（CM-REQ-03）
- 停止：確定した文字を残して待機に戻る。「音声を入力しました。必要なら直してから投稿してください」
- キャンセル：始める前の本文に戻して待機に戻る（その回に認識した文字はすべて捨てる。WBS の D-10）。「音声入力を取り消しました（始める前の文章に戻しました）」
- 待機に戻ったら、本文の欄にフォーカスを戻す（続けて手で直せる。VC-REQ-03・VC-09）
- 連打：聞き取り中に「音声で入力」は押せない（隠れる）。停止・キャンセルは、聞き取り中の 1 回だけ効く（VC-22・23）
- 画面を離れるとき（ほかの画面へ移る、再読み込み）は、聞き取りを止める（`pagehide`。VC-24）

#### 本文への反映（VC-REQ-03・04・08）

- 確定した文字（`isFinal`）だけを本文に足す。確定前の文字は、状態の欄に途中経過として出すだけ
- 始める前の本文の後ろに足す（既存の文字を消さない。WBS の D-10 の「追記」）。2 回目以降も、その時点の本文の後ろに足す
- 認識した文字の改行と、行・段落の区切りは空白にする。制御文字と書式文字は取り除く（絵文字をつなぐ U+200D は残す）。本文は改行と見えない文字を受け付けないため（phase2-spec.md の「5. 画面 > 入力チェック（変更。投稿・編集共通）」、WBS の D-11）
- 100 文字を超えても、音声の側では切り詰めない。投稿したときに、これまでどおり「100 文字以内で入力してください」で断る（本文は残るので、直して送れる）
- 文字は `textarea` の `value` と `textContent` にだけ入れ、HTML として解釈させない。「script」などと話しても、文字として入るだけ（VC-30）

#### 失敗したとき（VC-REQ-06・11）

失敗しても、待機に戻り、本文の欄はそのまま使える（手で入力できる、もう一度試せる）。聞き取りは毎回新しく作るので、前の失敗の処理が残らない（VC-21）。

| 理由（`error`） | 状態の欄に出す文言 |
|---|---|
| `not-allowed`・`service-not-allowed`（マイクを許可しなかった、あとから拒否した） | マイクの使用が許可されていません。ブラウザの設定で許可するか、キーボードで入力してください |
| `audio-capture`（マイクがない） | マイクが見つかりません。マイクをつなぐか、キーボードで入力してください |
| `no-speech`（何も話さなかった） | 音声が聞き取れませんでした。もう一度お試しください |
| `network`（通信できない） | 通信できず、音声を認識できませんでした。時間をおいてお試しいただくか、キーボードで入力してください |
| そのほか | 音声を認識できませんでした。もう一度お試しいただくか、キーボードで入力してください |
| `aborted`（キャンセルしたとき） | 出さない（キャンセルの文言を出す） |

- 状態や文言は、テンプレートの `data` 属性で渡す（画面の文言を JavaScript に書かない）
- 音声をサーバーに送らないこと、録音しないこと、HTML として解釈させないことは、`VoiceInputScriptTest` が `voice-input.js` に使ってはいけない API（`fetch`・`XMLHttpRequest`・`MediaRecorder`・`getUserMedia`・`innerHTML` など）が書かれていないことで確かめる（JavaScript のテストの仕組みがないため）
- 認識の精度は保証しない（ブラウザ・端末・通信・認識のサービスによる。WBS の「04_テスト計画 > 5. 結果記録のルール」）

### 写真の表示（今日のつぶやき・日記表示）

写真を添付したつぶやきにだけ、本文の下にサムネイル（高さ 160px まで）を出す。写真のないつぶやきには何も出さない（PH-REQ-11）。

- 部品は `templates/fragments/post-photo.html`（`thumbnail(post)`）。今日のつぶやき（`home.html`）と日記表示（`diary.html`）で使う
- サムネイルを押すと、新しいタブで元の大きさの写真（`/posts/{id}/photo`）を開く
- 写真を取れなかったとき（DB の障害など）は、ブラウザが代わりの文「添付した写真（新しいタブで開く）」を出す。本文はそのまま読める
- つぶやきの詳細画面はないので（phase1-spec.md・phase2-spec.md）、詳細画面は作らない。検索の結果には写真を出さない（本文の一部と日付を出す画面なので）
- 画面に渡すつぶやき（`PostItem`・`PostView`）は、写真の有無（`hasPhoto`）だけを持ち、写真のデータは持たない。写真の有無は、その日のつぶやきの ID をまとめて 1 回で問い合わせる（つぶやきごとに問い合わせない。N+1 にしない）

| 写真 | 5MB まで | 写真は 5MB 以内にしてください |
| 写真 | JPEG か PNG（中身で判定する） | 写真は JPEG か PNG にしてください |
| 写真 | 幅・高さ 12,000 画素まで、かつ 5,000 万画素まで | 写真の画素数が多すぎます（5000 万画素まで） |
| 写真 | 画像として読める | 写真を読み込めませんでした。別の写真を選んでください |

- ファイル名も中身も空の部分（写真を選ばなかったときにブラウザが送る部分）は、写真がないものとして扱う。ファイル名があれば、中身が空でも写真として扱い、「空です」で断る（空のファイルを選んだのに、黙って写真なしで投稿しない）
- 写真の決まりで断ったときは、本文を残して画面を出し直し、写真の欄にメッセージを出す（選んだ写真は残らない）
- 枚数はフォームの入力チェック（`PostForm`）、それ以外は service（`PhotoValidator`）で確かめる。上限・形式は仕様が変わりうる業務ルールなので、エンティティと DB には入れない（CLAUDE.md の「入力の検証（多層防御）」）

## 6. 処理の詳細

### つぶやきの投稿 `POST /posts`（変更）

1. フォームの入力チェック（本文と写真の枚数）
2. 写真があれば、controller が `MultipartFile` から、形式（ブラウザが送った `Content-Type`。なければ `application/octet-stream`）とバイナリを取り出して `PhotoUpload`（service の record）にし、`PostService#create` に渡す。service は Web の型（`MultipartFile`）を知らない
3. `PostService#create` は、これまでどおり上限の確認 → カテゴリの分類（Claude API。トランザクションの外）→ 保存の順に進める。写真は、つぶやきと**同じトランザクション**で保存する。どちらかが失敗したら、両方とも保存されない
4. ログ（INFO）に、写真の有無と大きさ（バイト）を足す。写真の中身・ファイル名は出さない（ファイル名に個人的な内容が入りうるため。CLAUDE.md の禁止事項「ログ」と同じ考え）

- 分かっている制約：開発の設定（`application.yaml` の `org.hibernate.orm.jdbc.bind: TRACE`）では、SQL のバインドパラメータのログに、写真のバイナリが 16 進でそのまま出る（2026-11-20 に 1.5MB の写真で確かめ、約 700 万文字の 1 行になった）。本番は `INFO` にしているので出ない（CLAUDE.md の「本番のコンテナ」）。開発で写真を何枚も試すときは、この設定を一時的に `INFO` にする

### つぶやきの編集 `POST /posts/{id}/edit`（変更）

controller が、編集フォームから写真の変え方（`service/PhotoChange`。sealed interface）を決めて `PostService#edit` に渡す。

| 変え方 | 条件 | 処理 |
|---|---|---|
| `Keep` | 写真を選ばず、「写真を外す」もない | 写真に触れない |
| `Replace` | 写真を選んだ | 写真があれば行を書き換える（`PostPhoto#replace`）。なければ新しく添付する |
| `Remove` | 「写真を外す」にチェック | 写真の行を消す（なければ何もしない）。本文は残す |

1. `Replace` なら、写真を確かめる（「写真の検証」）。受け付けない写真なら、Claude API を呼ばず、何も変えずに断る
2. これまでどおり、つぶやきを読み直す → カテゴリの判定（トランザクションの外）→ 保存（トランザクションの中）。写真の変更も、本文・カテゴリと**同じトランザクション**で行う。どれかが失敗したら、どれも変わらない（差し替えに失敗しても、前の写真が残る）
3. 写真を変えても、つぶやきは「編集済み」にしない（「編集済み」は本文を直したときの印）
4. 自分の今日か昨日のつぶやきでなければ、これまでどおり「つぶやきが見つかりませんでした」でトップへ戻す。写真にも触れない（PH-REQ-08）
5. ログ（INFO）に、写真の変え方（`Keep`・`Replace`・`Remove`）を足す

### 共通の決まり（CM-REQ-01〜05）

- 本文の決まり（CM-REQ-01）：100 文字まで・改行なし・見えない文字なし・1 日 16 件は、これまでどおりフォーム（`PostForm`・`PostEditForm`）・`Post`・DB と、`PostService` の上限の確認で守る。写真付きの投稿も音声で入れた本文も、同じフォームと同じ `PostService#create` を通るので、別の決まりにならない
- AI に渡すもの（CM-REQ-02）：日記の生成（`ClaudeService`・`DiaryGenerationService`）とカテゴリの分類（`PostCategoryClassifier`）には、これまでどおり本文（文字）だけを渡す。写真も音声も渡さない（料金も増えない）。`AiInputTextOnlyTest` が、これらのクラスが写真の型（`PostPhoto`・`PhotoUpload` など）をフィールド・引数・戻り値に持たないことを確かめる
- 操作（CM-REQ-03）：写真の欄・「写真を外す」・音声のボタンは、どれもラベル付きの `input` か `<button type="button">` で、キーボードでたどれる。状態は文字でも出す（音声の状態の欄、写真のメッセージ）。プレビューの取り消しや音声の終了のあとは、操作していた欄にフォーカスを戻す
- エラー（CM-REQ-05）：写真は理由ごとの文言（「5. 画面 > 入力チェック（追加）」）、音声は理由ごとの文言（「5. 画面 > 音声入力」）を出し、どちらも本文を残す。手入力にいつでも切り替えられる

### 写真の取得 `GET /posts/{id}/photo`

ログイン中のユーザーの、自分のつぶやきに添付した写真を返す（PH-REQ-08・12・13）。

1. `post_photos` を、つぶやきの ID とログイン中のユーザーの ID の両方を条件にして読む（`PostPhotoRepository#findByPostIdAndUserId`）。ID だけでは読まない（CLAUDE.md の禁止事項「他人のデータ（IDOR）」）
2. 見つからなければ 404（本文なし）。ほかのユーザーのつぶやき・写真のないつぶやき・削除したつぶやき（写真も `ON DELETE CASCADE` で消えている）を区別しない。画像の要求なので、エラー画面の HTML は返さない。service が WARN で記録する
3. 見つかれば、写真のデータをそのまま返す
   - `Content-Type`：保存したときにデータから決めた形式（`image/jpeg` か `image/png`）。ブラウザが送った形式は保存していない
   - `Content-Disposition`：`inline; filename="photo.jpeg"`（または `photo.png`）。アップロードしたときのファイル名は保存も表示もしない（ファイル名に個人的な内容や HTML が入りうるため。PH-REQ-12）
   - `X-Content-Type-Options: nosniff`：Spring Security が付ける。ブラウザに形式を推測させない
   - キャッシュ：Spring Security の既定（`no-store`）のまま。写真は個人的なものなので、共有の端末やプロキシに残さない。画面を開くたびに DB から読むが、1 日 16 枚までなので負荷は小さい
- 日付は問わない（日記表示から過去の写真も開ける）。投稿した本人なら、編集できない日のつぶやきの写真も見られる
- 未ログインなら、ほかの画面と同じくログイン画面へ移る
- 写真は公開の URL やバケットに置かず、この経路でだけ返す

### 写真の検証

`service/PhotoValidator#inspect` が、次の順に確かめる。どれかで断ったら `InvalidPhotoException`（理由つき）を投げ、何も保存しない。`PostService` は、上限の確認と Claude API の呼び出しより前に確かめる（受け付けない写真に料金をかけない）。断ったときは、理由と大きさを WARN で記録する（中身は出さない）。

1. 空でない
2. 5MB（`MAX_BYTES`）以下。ちょうど 5MB は受け付ける
3. 形式：データの先頭のバイト（マジックナンバー）で JPEG（`FF D8 FF`）か PNG（`89 50 4E 47 0D 0A 1A 0A`）かを決める。ブラウザが送った `Content-Type` とファイル名は使わない（拡張子・MIME の偽装を通さない）。GIF・HEIC・WebP は受け付けない
4. 画素数：ImageIO でヘッダーだけを読み、幅・高さが 12,000 画素（`MAX_SIDE`）以下、幅 × 高さが 5,000 万画素（`MAX_PIXELS`）以下か。画像のデータを展開する前に確かめる（小さなファイルが巨大な画像に展開される、解凍爆弾への備え。WBS の D-03）
5. 中身：最後まで読み込めるか。100 万画素ほどになるよう間引いて読む（メモリを使いすぎないため）。途中で切れたデータは、ImageIO が例外ではなく警告を出すので、警告も壊れているとみなす

- 保存する形式（`post_photos.content_type`）は、3. で決めたもの（`image/jpeg` か `image/png`）
- 撮影位置などのメタデータ（EXIF・GPS）は取り除かない。写真を見られるのは投稿した本人だけなので（PH-REQ-08）、ほかの人に位置が漏れない。取り除くには画像を書き出し直す必要があり、画質と向きの情報（EXIF の回転）を失うため（WBS の D-08）。ほかの人に写真を見せる機能を作るときは見直す
- CMYK の JPEG など、ImageIO が読めない JPEG は「読み込めませんでした」になる

### 写真の保持と障害のとき（PH-REQ-07・10）

- 写真はアプリの DB に保存するので（「2. 写真の保存先（PostgreSQL）」）、アプリやコンテナを再起動・作り直しても消えない。アプリのディスク（一時的な領域）には書かない
- 写真の保存・差し替え・削除は、つぶやきと同じトランザクションで行う。DB への書き込みが途中で失敗したら、つぶやきも写真も保存されない（写真だけ、つぶやきだけが残ることはない）。外部のストレージを使わないので、DB とストレージの食い違い（孤立したファイル、消えた写真を指す参照）は起きない
- 想定外の失敗（DB に接続できないなど）は、これまでどおり `RequestLoggingFilter` が ERROR で記録し、500 のエラー画面（「時間をおいて、もう一度お試しください」とエラー ID）を出す。入力した本文と写真は残らないので、もう一度入力して送る
- 写真を取れなかったとき（`GET /posts/{id}/photo` の失敗）は、サムネイルの代わりの文が出て、本文はそのまま読める（「5. 画面 > 写真の表示」）
- 送信ボタンの連打は、これまでどおり `form-submit.js`（`js-submit-once`）が 2 回目以降を止める。写真付きの投稿も同じ

### アップロードの大きさ（設定）

- Spring の既定（1 ファイル 1MB）では、スマートフォンやカメラの写真の多くが送れない。`spring.servlet.multipart.max-file-size` を 10MB、`max-request-size` を 11MB（写真 + 本文などのフォームの値）にする
- 受け付ける上限（5MB）より大きくしているのは、上限を少し超えた写真にも「5MB 以内にしてください」を出すため（5MB を超えた写真は、`PhotoValidator` が断る）
- 10MB を超えるリクエストは、Spring と Tomcat が受け取らない。そのときは汎用のエラー画面になる（画面からは、ブラウザの確かめで 5MB を超える写真を送らせない）

## 7. セキュリティ

- CSRF：`multipart/form-data` のフォームも `th:action` で送り、CSRF のトークンを埋め込む（CLAUDE.md の禁止事項「CSRF」）
- 写真はログイン中のユーザーのつぶやきにだけ付く（新しく作るつぶやきに付けるので、他人のつぶやきを指定する経路はない）
- 写真を返すのは `GET /posts/{id}/photo` だけで、ログイン中のユーザーのつぶやきに限る（「6. 処理の詳細 > 写真の取得」）
- 認証・CSRF・セッション（CM-REQ-04）：写真の取得も、写真付きの投稿・編集（`multipart/form-data`）も、ほかの画面と同じく Spring Security のログインと CSRF の対策の中に置く。認可の設定（`permitAll` の対象）は変えない。フォームは `th:action` で送り、CSRF のトークンを埋め込む
- 音声はサーバーに届かないので、サーバーの守りの対象にならない（「5. 画面 > 音声入力」）
- 写真の形式・中身は、サーバーがデータから確かめる（「6. 処理の詳細 > 写真の検証」）。ブラウザの確かめ（`photo-input.js`）は使い勝手のためで、守りはサーバーに置く

## 8. テスト

- `PostPhotoTest`：コンストラクタの内部一貫性（`null`・空の形式・長すぎる形式・空のデータを拒否する、データを複製する）
- `PostServiceTest`：写真ありの投稿で、つぶやきと写真を同じトランザクションの中で保存する。写真なしなら写真を保存しない。上限に達していたら写真も保存しない
- `PostControllerTest`：写真なし・写真 1 枚で投稿できる。写真 2 枚は入力チェックで拒否し、service を呼ばない。ファイル名も中身も空の部分は写真なし、ファイル名のある空のファイルは写真として渡す。受け付けない写真は理由を出し、本文を残す
- `PhotoValidatorTest`：JPEG・PNG を受け付け、GIF・HEIC・偽装した HTML やテキスト・空・5MB を超える・途中で切れた・画素数が上限を超えるものを断る。5MB ちょうど、画素数の上限ちょうどは大きさ・画素数では断らない。テストの画像は ImageIO で作り、大きすぎる画素数は PNG のヘッダーだけを組み立てて試す（`TestFixtures`）
- DB の制約（主キーで 2 枚目を拒否する、検査制約、つぶやきの削除で写真も消える）は、テストが DB につながないので、開発の DB でトランザクションの中で確かめ、最後にロールバックする（CLAUDE.md の「テスト」）
